Troubleshooting

Find the message you saw, or the symptom closest to it. If nothing here fits, see Reporting bugs.

Registering and the license

Section titled “Registering and the license”

Registering

Section titled “Registering”

If pressing Register in the Unregistered window does not work, the window says why.

Message What to do
The registration key is not valid. Check the key and the email address it was issued to. Both must match.
The registration server could not be reached. Check the network connection and try again. Registering needs the internet once. Check the connection, a proxy or a firewall, then try again.
The registration server’s reply could not be verified. Try again later. Something between you and the server changed the reply. Try again later, or from another network.
The license could not be saved to and a path Check that you can write to %LocalAppData%\MXmlBench.
The license was issued in the future by this machine’s clock. Check the clock, then try again. Set the Windows clock to the right date and time.

Once registered, the license is checked on this machine only, with no internet needed.

The license stopped working

Section titled “The license stopped working”

When the license is missing, expired or does not fit this machine, M-XML Bench opens the Unregistered window at start, with a line saying why:

Line What to do
This machine is not registered. Register it.
The license expired on and a date Register again with a current key. For a new key, email support@redlineip.com.
The license is for a different machine. The license file came from another machine, or this one’s hardware changed. Register again here.
The license file is damaged or was edited. Register again. It replaces the file.

To check from a terminal, run:

It prints the license status and where the license file is.

A manuscript came out as one big conflict

Section titled “A manuscript came out as one big conflict”

If git merge turns a whole manuscript into one conflict, with all of ours above all of theirs, this machine is not registered or its license has lapsed. The driver says so:

Nothing is lost: both whole versions are in the file. Register, then run git merge --abort and merge again, or resolve this one in the Workbench as it is.

A whole-file conflict also happens when git itself cannot be started; see git was not found.

Merging

Section titled “Merging”

The file opened as a text merge

Section titled “The file opened as a text merge”

The driver’s XML merge is for Duck Creek manuscripts only. Anything else gets git’s normal line merge, and the ribbon says why:

The ribbon says Why What to do
Text merge: the root is <settings>, not <ManuScript>, so git’s line merge ran. The file is not a manuscript. Nothing. This is expected.
Text merge: ours is <ManuScript> and theirs is <Other>, so git’s line merge ran. The two sides have different root elements. Check that the right files are being merged.
Text merge: this file is not XML, so git’s line merge ran. The file does not read as XML at all. Nothing, if that is expected.
Text merge: theirs is not well-formed XML at line 10, column 38, so git’s line merge ran. One side is broken on its own branch. Click the line and column to see the spot. Fix it in the merged pane, and on that branch too.
Text merge: the XML engine could not read the manuscript, so git’s line merge ran. The manuscript uses something the XML engine does not read yet, such as HTML entities like &nbsp;. Duck Creek loads these fine. Resolve it as text. The driver prints the same reason during git merge.

Text merges explains what works differently.

Save & finish will not write the file

Section titled “Save & finish will not write the file”
What you see What to do
The button is grayed out. Conflicts are still open. Hover the button for the count, settle them, or use Keep for later.
1 stray conflict marker line remains. A marker line is left over, often from a hand edit that deleted one side but not its marker. Find the line in the merged pane (it starts with seven <, =, > or | characters) and delete it.
Not written: the result is not well-formed XML at line 12, column 5. and a reason The merged result would not load in Duck Creek. Click not well-formed in the merged pane’s header to jump to the spot, and fix it. See When a file will not parse.
Not written: and another reason The file could not be written, for example because another program has it open. Close that program and try again.

git says the merge failed

Section titled “git says the merge failed”

git prints this when the Workbench closes without writing the file: after Keep for later, after closing the window, or after pressing Cancel in the Unregistered window. The file stays conflicted and nothing is lost. Run git mergetool again to go back to it. If you kept the merge for later, it opens where you left off.

A kept merge was ignored

Section titled “A kept merge was ignored”

A kept merge for policy.xml belongs to different inputs and was ignored. You chose Keep for later on this file, but the merge has changed since, for example because it was aborted and started again. The driver ran fresh. The old kept merge cannot be applied to the new inputs.

git was not found

Section titled “git was not found”

The driver and the Workbench start git from your PATH, never from the current folder.

Message Where
git was not found, so git integration is skipped. Setup
MXmlBench: git was not found on PATH. Install git, then run this command again. MXmlBench.Driver.exe --git-setup
git could not be started, so the line merge could not run. Check that git is on PATH. The Workbench, opening a case
git could not be started: git.exe was not found on PATH. The Workbench, From git
MXmlBench: git could not be started, so the line merge did not run. The driver, during git merge

Install git for Windows, or add its cmd folder to PATH, then open a new terminal. If setup skipped the git steps, connect them now:

git says the merge driver was not found

Section titled “git says the merge driver was not found”

git’s config still points at an install that has moved or been removed. Reinstall, or remove the old settings with MXmlBench.Driver.exe --git-setup remove from a current install and connect again with install. --git-setup status shows what git points at now.

git mergetool opens a different tool

Section titled “git mergetool opens a different tool”

Another tool is still git’s default. Check with:

Run MXmlBench.Driver.exe --git-setup install --mergetool to make M-XML Bench the default, or open it for one run with git mergetool --tool mxmlbench.

Could not open the merge

Section titled “Could not open the merge”

When git mergetool or a git client starts the Workbench with arguments it cannot use, it shows Could not open the merge with the reason, such as Ours not found or Output folder not found. The file is unchanged. Press Close to return to git, which leaves the file unmerged.

If a git client opened it, check the client’s arguments against Git clients.

Other

Section titled “Other”

The layout reset in a second window

Section titled “The layout reset in a second window”

Another M-XML Bench window is open, so this one uses the default layout and does not keep layout changes. Only one window at a time keeps your layout, View options and recent cases. Close the other window to get them back.

Logs for support

Section titled “Logs for support”

If the Workbench crashes, it writes %LocalAppData%\MXmlBench\workbench.log. The browser engine inside it writes cef.log in the same folder. Logs can hold file and folder names, so email them to support@redlineip.com rather than attaching them to a public issue.
