The window

Opening a merge

Section titled “Opening a merge”

Each merge you open is a case: a base, an ours and a theirs file, and the merged result the driver made from them. There are three ways to open one, and they differ in what the Workbench can do once it is open.

From git mergetool

Section titled “From git mergetool”

git mergetool, or a git client that runs it for you, opens one conflicted file. The title bar reads git mergetool · and the file name, and the window works on that file only: there is no Open case, no + tab and no Save as. When you finish, the result goes straight back to git. Git clients covers launching from an editor or a GUI client.

From the Start menu

Section titled “From the Start menu”

Opened on its own, the Workbench shows the start screen.

  • Three files takes a base, an ours and a theirs file. Type the paths or use Browse, then press Run driver. The panes are labeled with the file names.
  • From git takes a repository in the middle of a merge. Choose the repository with Browse; the Workbench lists its conflicted .xml files. Pick one and press Run driver. The Workbench reads the three versions from git’s index, and labels the panes with the current branch, the merge base’s short commit id, and the branch being merged in.
  • Recent lists the last five cases, marked files, git or resume. Click one to open it again, or × to remove it from the list.

Either way, the driver runs on the three files and the result opens on the bench. The files you picked are not changed until you save.

More than one case

Section titled “More than one case”

Outside git mergetool, each case opens in its own tab. Press + at the end of the tab bar, or Open case on the Session tab, to put another one on the bench. Open recent on the same tab lists the recent cases.

A second window

If one Workbench window is already open, a second one starts with the default layout and does not remember layout changes or recent cases. When git mergetool opens it, the ribbon says so. Close the first window if you want your own layout back.

The layout

Section titled “The layout”
Part Where What it is for
Title bar Top The ribbon tabs (Session, Merge, View), the file name under git mergetool, and the window controls. Drag it to move the window; double-click it to maximize.
Ribbon Under the title bar The buttons for the tab you picked, the merge’s status on the right, and the finishing buttons at the far right.
Tab bar Under the ribbon One tab per open case, and one per table you are reviewing. A dot on a tab means unsaved edits.
Structural diff Left Every element that changed and what the driver did with it. See Read the Structural diff.
ours, base, theirs Top right The three inputs, read-only.
Line strip Under the inputs One line compared across the three inputs, piece by piece.
merged result Bottom right The file that will be saved. You can edit it.
Drawer Bottom The Conflict report and Case tabs.

Drag any divider to resize the panels. The Workbench remembers the sizes, the panels you have open and the View options on this machine.

The input panes

Section titled “The input panes”

ours is your side, theirs is the side being merged in, and base is the version both started from. In each pane:

  • Lines that side changed are green, and the changed words are highlighted.
  • Lines inside an open conflict are red.
  • Hatched gaps keep matching lines side by side. A gap can carry a note: only in ours marks lines one side added, and moved by ours · at line 12 marks an element that side moved. Click a moved by note to inspect that element (see Field Inspect).
  • A red squiggle marks a spot where the file is not well-formed XML. Hover it for the reason.

To make room, close base with the ✕ in its header, and bring it back with ▸ base or Base on the View tab.

The line strip

Section titled “The line strip”

Click a line in ours, base or theirs, and the line strip compares it with the matching lines in the other two, piece by piece. Each difference gets a box with a tag: ours only, theirs only, agreed where both sides made the same change, or both where they disagree. Inside the box, the base value comes first, then ours, then theirs.

The header names the line number in each pane and counts the differences. On a line inside a conflict, the ours and theirs values in the box are buttons that take that side.

The merged result

Section titled “The merged result”

This is the file the Workbench will save. It starts as the driver’s output, with conflict markers wherever the driver left a conflict. Its header shows 1 conflict, not well-formed or resolved. Click not well-formed to jump to the spot.

The drawer

Section titled “The drawer”
  • Conflict report lists every conflict and silent drop the driver reported when the case opened, with the element’s path and the reason. It is a record of the driver’s output, so it does not change as you resolve. The reasons use git’s names, local and remote, for ours and theirs.
  • Case collects what you tell the driver engineer when you report a wrong decision.

▾ hide folds the drawer down to its tabs. ▴ show, either tab, or Conflict report on the Session tab opens it again.

The ribbon

Section titled “The ribbon”

The ribbon has three tabs, picked in the title bar. Merge is open when a case loads.

Session tab

Section titled “Session tab”
Group Button What it does
FILE Open case Opens the start screen over the current case, to add another tab. Not under git mergetool.
Open recent Lists recent cases. Not under git mergetool.
Reload Runs the driver again on the case’s input files and starts the merged result over.
MERGETOOL WRITES TO Under git mergetool, in place of FILE: the file the result goes to.
Reload Runs the driver again on git’s inputs. After a resumed merge it is a menu: Reload kept merge or Start over from git’s inputs.
OUTPUT Conflict report Shows or hides the drawer.
Save as Saves the merged result to a file you choose. Not under git mergetool.
HELP License Shows who this machine is registered to and until when.
About A short description of M-XML Bench.

Reload asks first if you have edited the merged result, since it replaces your edits.

Merge tab

Section titled “Merge tab”
Group Button What it does
NAVIGATE Prev, Next Step to the previous or next conflict. The CONFLICT readout between them shows which one you are on, for example 1 / 3.
Find Opens the command palette, to run a ribbon command or jump to a changed element by typing part of its name.
RESOLVE Take ours, Take theirs, Take both, Isolate, Undo Settle the conflict you have stepped to. See Resolving conflicts.
COMPARE Structure Shows or hides the Structural diff.
Reformat Re-indents the merged result, keeping the file’s own indent and line endings. Available once no conflicts are left, and never in a text merge.

View tab

Section titled “View tab”
Group Button What it does
DISPLAY Wrap Wraps long lines in every pane.
Whitespace Shows spaces and tabs.
Align lines Keeps matching lines side by side across the panes, with hatched gaps. On by default.
Zoom Makes the text larger. Its menu has Zoom in, Zoom out and Reset zoom.
Fold Fold all collapses every element; Unfold all opens them again.
PANES Base Shows or hides the base pane.
Sync scroll Scrolls the panes together. On by default.
Line strip Shows or hides the line strip. On by default.

A table tab has its own Resolve and View tabs; see Tables.

Status and finishing buttons

Section titled “Status and finishing buttons”

The right end of the ribbon shows where the merge stands and holds the buttons that end it.

  • 1 conflict unresolved counts the conflicts still open in the merged result. It changes to no conflicts when none are left.
  • unresolved fallbacks counts groups of elements the driver paired by position rather than by name. It asks for a glance, and never blocks saving. See Unresolved fallbacks.
  • Notes about the file appear here too: why it was merged as text, what stray characters were removed, and whether the last save worked.
  • Under git mergetool the buttons are Keep for later and Save & finish. Otherwise they are Run, which runs the driver again, and Save result. Saving and finishing covers both.
